Getting Started

This describes the current Sonuvi installation boundary. Sonuvi is a moOde-focused enhancement platform: it runs a web UI and API on an app host and uses MPD, moOde, SSH, and HTTP integrations to provide richer playback, metadata, queue, display, and controller experiences.

Recommended topology

Run Sonuvi on a separate Linux/Raspberry Pi host from the moOde player. The split keeps UI/API work independent from the audio host while allowing the API host to reach moOde over the LAN.

RoleTypical serviceDefault port
Sonuvi UIstatic HTML/CSS/JavaScript8101
Sonuvi APINode/Express service3101
moOde MPDMPD on the player host6600

Install

Use the Sonuvi Server operations guide. The production model is systemd (sonuvi-api.service, sonuvi-web.service), immutable releases under /opt/sonuvi, and writable state under /var/lib/sonuvi. PM2 and the legacy installer are not the current production startup mechanism. The old installer and file-push helper fail without making changes.

Main includes the accepted runtime and release builder/verifiers. Obtain an approved artifact and deployment procedure; the remaining host activation and fresh-install gaps are listed in the source baseline. Do not treat a main checkout or unit templates as a complete installation bundle. Historical validation notes remain in install-and-validation.md.

Configure the first connection

  1. Open config.html on the Sonuvi UI host.
  2. Set the moOde/MPD host and port.
  3. Preserve the approved operator authentication and separate native-device pairing.
  4. Use the release's validated configuration/protected environment and managed SSH paths.
  5. Config Save edits only supported non-secret settings and verifies media-path

readback after authentication. It is not an installation/migration mechanism. Restart requires the separately configured narrow Sonuvi-pair policy; when unavailable, an administrator must restart the pair and verify health. Never weaken the sandbox or restart legacy units.

Use config-interface.md for the page model and config-network-and-runtime.md for connection and path verification details.

Verify the first run

Check these in order:

  1. GET /now-playing returns JSON from the API.
  2. GET /next-up returns the current queue view.
  3. app.html or a controller page loads from the UI host.
  4. MPD transport changes from the controller reach moOde.
  5. The display route loads if moOde is configured to use Sonuvi.

The operator-facing checks are collected in configuration-and-administration.md and install-and-validation.md.
