# HTTPS 8443 audit — 2026-11-11

## Observed deployment, not a network redesign

The current VM is `10.0.0.65`, running release
`sonuvi-91e195bde790dd43b7a0c5ba23507e4b4e25803eb828cddcb7e8de5bf995d10f`.
This audit did not change its listeners, certificates, identities, or services.

1. **Origin and ownership.** Server commit `98bb767` introduced the direct LAN TLS listener during the November 11 browser repair. The prior temporary Mac TLS/SSH proxy used port 9444. The replacement is inside `sonuvi-web.service`, running as `sonuvi`, configured by `60-vm-parity-browser.conf`; it is not Caddy and is not a separate 8443 daemon. The implementation is reusable Server code, but the selected IP, port, private CA and drop-in are **VM-specific deployment configuration**, not a finished fresh-install/discovery architecture.
2. **Request flow.** HTTPS8443 terminates TLS in Node and serves the release's positive-allowlisted static web assets. The same process listens on HTTP8101, redirects GET/HEAD to the configured HTTPS origin with307, rejects unsafe HTTP methods, and has two exceptions: the public CA download and loopback-only `/release.json` health read. It does **not** proxy8443 through8101. Authenticated allowlisted browser requests are forwarded directly to API `127.0.0.1:3101`.
3. **Browser identity.** Reverse pairing creates a P-256-attested browser controller presentation. An existing authorized controller approves its verification code. The web service retains the mobile bearer server-side and issues a `Secure; HttpOnly; SameSite=Strict` opaque cookie; JavaScript receives a CSRF token, not the bearer. Sessions are origin-bound, bounded to at most eight hours/the underlying grant expiry, and persisted in a service-owned0700 directory with0600 atomic files. Cookie renewal does not extend the original grant.
4. **Proxy scope.** The gateway allowlists browse/state, playlist/podcast reads, artwork and animation routes. Host/Origin and cross-site checks apply; the permitted POST reads also require CSRF and validated bodies. It passes Range and selected media response headers and streams permitted upstream responses; animated-media URLs are rewritten to the same HTTPS origin. Custom playlist artwork uses the native playlist-artwork proxy. **This is not a general mobile API, administration, or audio-ticket proxy.** Ordinary playback mutations and broad browser audio-streaming parity must not be inferred from artwork/animation success. Native iPad504 playback uses its own native transport.
5. **Exposure and administration.** Live `ss` shows8443 and8101 on `0.0.0.0` (all IPv4 interfaces), API3101 on `127.0.0.1`, DLNA3102 only on `10.0.0.65`, SSDP UDP1900 on all IPv4 addresses, and SSH22 on IPv4/IPv6. The browser gateway does not forward `/v1/admin/*`, arbitrary `/config/*` writes, host commands or credentials. Native admin remains a separately authorized short-lived bearer over pinned SSH to the loopback API. No claim that an all-interface listener is confined by its bind address to the LAN; firewall/routing are separate controls. The VM has no nftables rules; Avahi and Tailscale are inactive. No TLS renewal references were found in the inspected cron locations.
6. **TLS lifecycle.** A VM-local private CA was generated by the one-time `vm-tls-prepare.py` script; the CA expires2036-11-08, the leaf2027-11-11. The leaf SAN is **only IP10.0.0.65**. Browser/OS trust requires importing and trusting this CA; downloading it over HTTP is not authenticated trust establishment and requires an independently checked fingerprint. TLS private material is supplied to the service through systemd credentials. No automatic renewal exists in the serving implementation or the inspected timer schedule. The leaf is loaded at process startup; renewed material would require an approved service restart. A different IP, `sonuvi.local`, or a Tailscale name is not covered by this leaf; no automatic address/certificate/origin migration exists. Origin changes also invalidate the persisted browser-session binding. Native SSH identity is separate and must not be conflated with TLS identity.
7. **Desired standard address.** Yes: a normal user-facing installation should offer a discoverable HTTPS URL without typing ports, preferably an advertised stable name on443. `https://sonuvi.local` is an **approved product goal, not an implemented VM cutover**. `.local` does not by itself supply a publicly trusted certificate. A supported design needs name uniqueness/discovery, OS trust onboarding or a validated domain alternative, certificate renewal, and a deliberate low-port listener/reverse-proxy policy. None is changed by this audit.
8. **Client impact.** iOS/tvOS should consume one declared, identity-bound web-controller URL for opening a browser; native API/admin/playback keep their reviewed transports and must not derive URLs by adding8443. Browser displays use the one HTTPS origin, never choose an API port. Tailscale needs a separately valid reachable name/certificate/origin policy; changing the URL to a tailnet IP will not satisfy this certificate. Legacy Pico/Mills/Seeburg integrations use separate legacy Track-Key endpoints and cannot be redirected to the cookie-paired browser gateway. Their destinations, HTTP expectations and auth remain unchanged; no cutover is authorized.

## Native Settings / installer architecture

**Current:** the API and web service have separate environment configurations. The API cannot reliably advertise the web origin simply by reading its own environment. Native Settings must not guess a browser address from its SSH address, API port or a hardcoded8443. The source configuration editor labels listener/TLS/discovery operations host-managed and does not export/import them.

**Target:** installer-owned, nonsecret web-access metadata bound to the stable Server identity should supply canonical origin, discovery name, trust status, expiry/renewal status and connectivity checks. Native clients can then show **Open web controller** and meaningful trust/setup state. Configuration transfer must preserve destination network identity and trust. Implementation of that installation/network contract needs its own bounded work; this audit does not authorize another network redesign.

**Evidence:** `https-live-audit.json`, `https-host-audit.json`, read-only HTTPS probes, installed source at `scripts/serve-public-web.mjs`, `src/lib/public-web-server.mjs`, `src/lib/controller-web-gateway.mjs`, and `src/lib/controller-browser-dispatch.mjs`. Production was not modified.
